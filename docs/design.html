→
中心用户 · 套餐 · 节点 · 订阅 · 审计
可部署在国内小服务器
↔
Gate主动连接中心 · 本地执行
管理 Xray / sing-box
代理流量：客户端 → Gate 上的内核 → 目标网站，不经过中心。中心只处理订阅获取、Gate 心跳与流量上报，以及管理页面。
角色内容状态
单机中心 + 本机 Gate 在同一进程；本机 Gate 仍走回环地址配对和同一套同步协议目标
管理端中心服务 + 内嵌控制台，默认监听 127.0.0.1:19810，由本机反代提供 HTTPS已有 现为 migate-control / migate-gate / migate-manage 三个程序，目标合并为一个 migate
Gate只跑 Agent，主动连中心，不开放管理端口。中心「添加 Gate」生成带一次性配对凭证的一行命令，执行后自动安装、配对、上线已有 主动连接与配对；目标 一行命令（现需手动 migate-gate pair）

存储

已有 PostgreSQL + Redis，只用 migate schema 与 migate: 前缀，不清空共享实例。

目标 只用 SQLite + 内置缓存，单机默认采用。手写 SQL 收进存储层；PG 咨询锁改为锁接口；jsonb 局部更新改为事务内读改写；Redis 用法（含 5 段 Lua）收进键值接口。两种后端跑同一套测试。

中心与 Gate 同步

已有 18 种带能力版本的零碎任务（如 routing.order.v1、inbound.enabled.v1），中心记录任务、Gate 回执。

目标 中心为每台 Gate 推送完整期望配置（带版本）；Gate 校验 → 应用 → 健康检查 → 失败回滚 → 上报实际状态。配对、升级、诊断等少数动作单独保留。

中心断线时结果状态
用户正在上网不受影响，Gate 照常转发已有
到期时间Gate 本地判断，到点停用已有
获取订阅 / 改配置获取不到，已导入的客户端继续可用；配置等中心恢复后下发已有
额度只用一台 Gate 的用户：剩余额度整份交给这台 Gate。多台 Gate：分块，块大小按最近使用速度定（目标约 24 小时，最少 32 MiB，不超过剩余额度）。新增 Gate 时先由原 Gate 确认收回多出的额度再分配目标 现为固定 32 MiB 分块、低于 25% 补充，Agent 只增不减（internal/agent/agent.go:747）

03内核与配置

只调用二进制
内核在哪运行用途
XrayGateVLESS + REALITY 等；应用前 xray run -test
sing-boxGate / 中心Gate 上跑 Hysteria2、TUIC 等，应用前 sing-box check；中心用它检查生成的 sing-box 订阅
mihomo中心用 mihomo -t 检查生成的 Clash 订阅；不在 Gate 上运行

获取与更新 目标

三个内核都以独立二进制调用，不引入它们的 Go 包，内核更新不需要 MiGate 发版。中心从上游 GitHub Releases 拉取（镜像回退 + 官方摘要校验），缓存后把 Gate 需要的推送过去；Gate 不访问 GitHub。每台 Gate 可单独锁定版本。

sing-box 官方发布包不含 with_v2ray_api，而按用户统计流量依赖它：由 CI 跟随上游标签按官方参数加上该标签自动编译，中心从那里拉取。

现状：GitHub Release 不含内核；内核只出现在旧的本地打包（deploy/core-packages.json），sing-box 为自编译的 1.14.3-migate.stats1。

按版本生成配置 目标

所有内核版本都用版本档案 YAML：支持的协议与字段、已移除的选项、兼容限制、默认值。档案是数据文件，可单独更新，也可由 AI 出草稿（见 06）。生成器按 Gate 实际安装的版本选档案。

已知例子：Xray 26.3.27 移除了 allowInsecure；Xray 26.10.17 的 REALITY 需要 MLKEM，与 sing-box 1.14.3 客户端不兼容，混合客户端保留 26.3.27。

自管理与端口

已有 内核使用独立目录（/opt/migate-gate/cores、/etc/migate-gate/cores）和独立 systemd 单元，不碰 x-ui。端口不得为 80 / 443 / 8443，自动分配范围 20000–60000。

目标 Gate 在心跳中上报本机正在监听的端口（读 /proc/net/tcp、tcp6、udp、udp6，能取到就附进程名）；中心分配时避开保留、已登记和已占用端口；Gate 应用前再查一次，被占用就失败并由中心重新分配。内核统计 / API 端口走同一套分配，只监听回环地址。

已知缺陷：现在的可用性试绑（internal/db/inbounds.go:961）在运行中心的机器上执行，分开部署时测的不是 Gate；统计端口固定为 127.0.0.1:19815（Xray）/ 19817（sing-box）。

04建节点与链式代理

目标
① 选协议VLESS / Hysteria2 / Trojan …
② 选 VPS从已连上的 Gate 中选，作为入口
③ 链式代理不用 / 家宽 SOCKS5 / 另一台 VPS 作出口
④ 完成端口、密钥、凭据、传输参数自动处理；可顺手勾选给哪些用户

伪装与场景

每个协议内置一套最稳的组合（如 VLESS 默认 REALITY + TCP），新手不需要懂。REALITY 伪装目标由 Gate 从内置列表实测：支持 TLS 1.3 与 H2、无跳转、延迟最低者入选。属于固定逻辑，不依赖 AI。

上游 MiGate 有 9 个场景模板与 REALITY 快捷选择；定义仍在 internal/db/inbound_capability.go，但当前控制台没有任何地方调用，入站仍是逐字段表单。

链式代理

流量路径：用户 → 入口 VPS → 出口（家宽 SOCKS5 或另一台 VPS）→ 网站。系统按第 ③ 步自动生成出站与路由，基于现有「按用户凭据路由到指定出站」能力。入口到出口这一跳的凭据由系统生成，流量只在入口计一次。

05用户与分发

目标
① 名称邮箱可选
② 套餐额度 + 期限（30 / 90 天 / 不限 / 自定义），可勾选每月重置
③ 节点勾选具体节点，或「全部节点」（以后新加的自动包含）
④ 保存自动生成凭据并下发 Gate，直接显示订阅链接与二维码

现状：开用户（邮箱 / 密码 / 额度 / 到期）与「节点访问授权」（选 Gate → 选入站 → 选用户，每次一个入站）是两个页面。续期、加额度、加节点目标都在同一窗口内完成。

多链接

每个用户最多 10 个链接，每个链接独立凭据，泄露或删除只影响这一个。额度按用户共用，按链接分别显示用量。新链接默认「我的全部节点」并自动包含新授权；手动挑选后不再自动加入。链接可一键重置，旧链接立即失效。

用户自建链式代理

生成一个新节点（如「香港 → 家宽」），出现在本人节点列表，任意链接可勾选。入口为本人已有节点；出口为家宽 SOCKS5 或本人有权限的 VPS 节点。只允许公网地址，拒绝本机、内网与云元数据地址；保存前 Gate 实测连接，不通即报错；流量只在入口计一次；管理员可按用户关闭。

管理员可见

每个用户的链接（节点、各自用量、最后使用时间、完整订阅地址）与链式代理（入口、出口地址 / 端口 / 用户名 / 密码）一律显示原文；可停用、删除、重置；用户的新建 / 修改 / 删除写入审计。用户之间互相看不到。

用户拿订阅

只有一个链接，客户端导入时按客户端类型自动给出格式。浏览器打开显示剩余流量、到期、二维码和 17 个客户端一键导入（Clash Verge、Mihomo Party、v2rayN / NG、Shadowrocket、Hiddify、NekoBox、Stash、Loon、Surge、QuanX、Karing 等）。导入与查看只要链接；管理链接与链式代理需要登录。

现状：一键导入只有 clash://（apps/console/src/pages/subscription.tsx）。机场订阅组可分给用户，其流量不经过 Gate，不计入额度。

06AI 配置助手

目标
AI 出草稿配置或版本档案 YAML
→
系统测试不通过 → 错误交回 AI 继续改
→
管理员看差异测试通过前不能点确认
→
确认生效旧版本保留，可退回

做什么

伪装与场景推荐（如「移动宽带、UDP 受限、看流媒体」）；分流规则与处理链生成；读取内核更新说明后提出版本档案修改，不用等项目发版；日志解读。

怎么测

由系统执行，不让 AI 运行：先用目标版本内核自检，再在回环地址临时起实例、用客户端内核真连一次，能查出握手不兼容这类问题；用完即删，不影响正在运行的节点。

边界

AI 不执行操作、不碰 Gate、不直接改正在用的配置。节点密码、UUID、订阅令牌不发给模型。提供方支持 Anthropic / OpenAI 协议与自定义 Base URL，Laya（原生 /v1/systemone）作为其中一种，也用于告警排序。模型故障不影响基础功能。

07上游吸收

好的吸收，繁琐的优化
MiGate设备与内核运维。上游页面是 React，按原交互移植（方案模板、REALITY 快捷选择、建节点时建客户端、分享链接与二维码），不改写成通用表单。
MiSub订阅管理。JS 逐文件迁移到 Go，以功能与上游一致为目标，本机 Node 运行原代码作对照；不再一律拒绝未适配字段。附加功能全部保留：公开页、公告、留言、客户端目录、分享、WebDAV 备份、外部管理 API、定时任务、6 套规则模板、17 种一键导入。
Sub2API只作框架参考：后台布局、认证流程、安装方式。不作为功能来源。
UIAble组件源码放在 packages/ui，基础控件优先使用。

逐项对照与缺口见 migration.html。

08安全底线

规则执行 · 模型辅助

人的身份

管理员登录二次验证；后端强制校验角色与资源归属，隐藏菜单不能代替鉴权。

登录限速、会话撤销、恢复机制。普通用户只能看到和管理自己的链接、节点、链式代理。

设备的身份

Gate 主动连中心；配对凭证短时、一次性；每台设备独立身份，可单独撤销。

Agent 只执行允许的业务操作，拒绝重放与跨设备指令，不提供任意 Shell。

行为与数据

记录谁、何时、对哪台设备、做了什么，以及结果。管理员可看所有用户配置原文。

观测缺失显示「未知」，不能显示正常或 0。私钥、令牌、真实订阅凭据不入仓库与文档。
